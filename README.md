# Closet — バーチャルロッカー＆コーディネーター

「自分のクローゼットを全部知ってるスタイリスト」。手持ちの服を登録すると、気温・行き先・直近の着用履歴から毎朝のコーデを3案提案。買い物では手持ちとの相性をチェックし、着用イメージもAIで生成できる。

## 機能
- **服の登録**：写真をまとめて選ぶだけ。裏で並列処理し、AIが属性を解析＋ブランド公式オンラインブティック風の商品写真に撮り直して、終わったものから自動でクローゼットに登録（NEWバッジ付き、あとから編集）
  - 同じ服の写真が何枚も混ざっていてもOK。AIが同じ現物ごとにまとめ、各写真を「全体・背面・ディテール（裏地・ボタン等）・タグ・着こなし見本・着用」に仕分けて1点として登録
  - 背面・ディテールの写真は公式サイトのディテールカット風に撮り直して商品ページの2枚目以降に。タグの写真はブランドや素材の判断に使う
  - 着こなし見本（袖のまくり方など）は「いつもの着こなし」として保存し、コーデ提案の着こなしのコツに反映
  - ブランドはロゴ・タグ・特徴的なデザインから推測（推測なら「AI推測」表示、手がかりが無ければ「ブランド不明」）
  - 胸のワンポイントロゴなどの目印を「ディテール」として読み取り、撮り直しで必ず再現させる
  - 服はモデル着用の寄りのクロップ、靴・バッグ・小物はスタジオのスチール撮影。床置きの型崩れやシワは本来の形に復元
  - 背面に特徴的なデザインが写っていれば2枚目に背面の写真も作る。自分で撮った背面の写真を追加することもできる
  - 小物は種類ごとに撮り分け（ピアスは一対のマクロ、時計は文字盤正面・10時10分、ネックレスはU字に広げて真上から など）。ピアス・時計・帽子・ベルトなどは2枚目に耳元・手首などの着用カットも作る
- **アイテム詳細**：公式通販の商品ページ風に、写真のスワイプ表示・ブランド・ディテール・アイテム情報を表示
- **コーデ写真から一括登録**：全身のコーデ写真からアイテムをまとめて検出・切り出し。手持ちと同じアイテムは自動で照合し、着用記録も残せる
- **アイテム編集**：全項目を編集可能。写真の差し替え、AIで再解析、着用写真の切り抜きを白背景の商品写真に整える「商品写真化」
- **今日のコーデ**：天気を自動取得（Open-Meteo）→ 気温と行き先でコードが候補を絞り込み → AIが3案を提案 → 存在しないIDや構成不足をコードで検証し、問題があれば再提案
- **フィードバック学習**：👍👎・「これ着る」・👎の理由を次回の提案に反映
- **買い物の相談**：商品スクショ → 似た服を持っているか、手持ちと何コーデ組めるか、買い/検討/見送り
- **コーデ相談**：自分のコーデ写真 → 手持ちのアイテムを使った改善案
- **試着**：本人の全身写真＋アイテムから着用イメージを生成（着崩しの指示もOK）
- **スタイリストの性格**：バランス / きれいめ紳士 / 攻め / ミニマリスト / 辛口
- **固定アイテム**：ピアス・ブレスなど毎日つける物は全コーデに自動で追加

## 設計方針
- ダミーデータ・モックは使わない。AIが失敗したらエラーを表示する
- 服の写真・履歴はまず**端末のブラウザ内(IndexedDB)**に保存。オフラインでも動く
- **クラウド同期（任意）**：設定タブで同期をONにすると、Cloudflare D1 にも保存され、同じ「同期キー」を入れた端末同士でクローゼットを共有できる。OFFのままならサーバーは何も保存しない
- 設定タブからバックアップの書き出し・読み込みができる

## 構成
- フロント：React + Vite（PWA、スマホのホーム画面に追加可）
- サーバー：Cloudflare Pages Functions（`functions/api/*`）→ Gemini API
- 背景切り抜き：`@imgly/background-removal`（ブラウザ内のWASM）

## Cloudflare Pages へのデプロイ
1. Cloudflare ダッシュボード → Workers & Pages → 作成 → Pages → Gitに接続 → `virtual_closet` を選択
2. ビルド設定
   - フレームワーク: なし
   - ビルドコマンド: `npm run build`
   - ビルド出力ディレクトリ: `dist`
3. 環境変数（設定 → 変数とシークレット）
   - `GEMINI_API_KEY`（シークレット）… 必須
   - `APP_PASSCODE`（シークレット）… 任意。設定すると、アプリの設定タブで合言葉を入れた人だけがAIを使える（公開URLでキーを無断利用されないため）
   - `GEMINI_MODEL` / `GEMINI_IMAGE_MODEL` … 任意。モデルを固定したい時だけ。未設定なら `gemini-flash-latest` などを順に試す
4. （クラウド同期を使う場合）D1データベースを作ってバインドする
   - Workers & Pages → D1 → データベースを作成（名前は例: `virtual-closet`）
   - Pagesプロジェクトの 設定 → バインディング → 追加 → D1データベース、**変数名 `DB`** で上のDBを選ぶ
   - テーブルは初回アクセス時に自動作成される（手動で作るなら `schema.sql`）
5. 環境変数・バインディングを追加・変更したら再デプロイする

## クラウド同期のしくみ
- 端末のIndexedDBはそのまま使い、変更（作成・更新・削除）を記録して `/api/sync/*` に送る。他の端末の変更は起動時・画面復帰時・1分ごと・編集の2秒後に取り込む
- 同じアイテムを複数端末で編集した場合は、後に編集した方が残る（レコード単位の後勝ち）
- 画像は内容のSHA-256をキーに別送（同じ画像は1回だけ送信、900KBごとに分割してD1に保存）
- データは同期キーごとに分かれ、サーバーにはキーのハッシュだけを保存。キーを知っている人は誰でも読み書きできるので共有しないこと
- 同期対象: アイテム・コーデ履歴・プロフィール設定・試着用の全身写真（登録キューと合言葉は端末ごと）

## ローカル開発
```bash
npm install
echo "GEMINI_API_KEY=xxxx" > .dev.vars
npm run build && npx wrangler pages dev dist --d1 DB=local-closet   # http://localhost:8788（D1はローカルに作られる）
```
