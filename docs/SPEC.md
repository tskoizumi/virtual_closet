# バーチャルロッカー＆コーディネーター 仕様書（Claude Code用）

## 0. 大原則（必ず守る）
- **ダミーデータ・モック・ハードコードの結果を一切使わない。** すべての画面は実際に登録されたデータとAIの実出力だけで動く。
- AIやAPIが失敗したら、**それっぽい代わりの値を出さずにエラーを画面に表示する**（失敗を隠さない）。
- ユーザーの写真や服のデータは**ブラウザ内（IndexedDB）に保存する**。サーバーはAIの中継役（APIキーを隠すため）。例外として、ユーザーがクラウド同期をONにした場合だけ、同期キー単位でCloudflare D1に保存する。
- AIが返すアイテムIDは必ず実在チェックする。存在しない服を提案させない。

## 1. コンセプト
「自分のクローゼットを全部知ってるスタイリスト」
- 朝：手持ちの服から、気温・行き先・直近の着用を踏まえたコーデを3案出す
- 買い物：買う前に手持ちとの相性を確認して、無駄買いを防ぐ
- 育つ：着た記録とフィードバックで提案が自分好みになっていく

## 2. 技術構成
- フロント：Next.js（App Router）＋TypeScript＋Tailwind。PWAとしてスマホのホーム画面に置けるようにする
- 保存：IndexedDB（Dexie.jsを使う）
- サーバー：Next.jsのAPI Routes（またはCloudflare Workers）。AI APIを中継するだけで、何も保存しない
- AI：画像を読めるマルチモーダルLLM。モデルは実装時点の最新版を確認して選ぶ。出力は**JSONスキーマで固定**する
- 背景の切り抜き：`@imgly/background-removal`（ブラウザ内のWASMで処理）
- 天気：Open-Meteo API（キー不要）＋ブラウザの位置情報。位置情報が拒否されたら、地名を手入力で受け付ける

## 3. データモデル
```ts
Item {
  id: string
  originalImage: Blob
  cutoutImage: Blob
  category: 'tops'|'outer'|'bottoms'|'shoes'|'bag'|'accessory'|'other'
  subcategory: string        // 例: オックスフォードシャツ
  colors: string[]
  material: string
  pattern: string
  formality: 1|2|3|4|5       // 1=部屋着 〜 5=フォーマル
  warmth: 1|2|3|4|5          // 1=真夏向け 〜 5=真冬向け
  seasons: ('spring'|'summer'|'autumn'|'winter')[]
  isFixed: boolean           // 毎日つける固定アクセ（ピアス・ブレスなど）
  notes: string
  createdAt: number
  wearCount: number
  lastWornAt: number | null
}

Outfit {
  id: string
  itemIds: string[]
  createdAt: number
  context: { tempC: number; weather: string; occasion: string; mustInclude?: string }
  reason: string             // AIの提案理由
  rating: 'up'|'down'|null
  worn: boolean              // 実際に着た（一番強いシグナル）
}

Profile {
  tasteMode: string          // きれいめ / カジュアル / 攻め など
  styleNotes: string         // 好み・NGを自由に記述
}
```

## 4. 機能（MVP）

### 4.1 服の登録
1. 撮影またはアップロード → 背景を切り抜く → 切り抜き結果をプレビュー
2. 切り抜き画像をAIに送る → 3章のフィールドをJSONで返させる
3. ユーザーが確認・修正して保存する（AIのタグは必ず編集できるようにする）
4. 連続撮影モード：保存したらすぐ次の撮影に移れるようにする（登録の手間を減らすのが最重要）

### 4.2 クローゼット一覧
- カテゴリ・色・季節で絞り込み
- 着用回数と最終着用日を表示し、「最近着てない」で並べ替えられるようにする
- 固定アクセのON/OFF切り替え

### 4.3 朝のコーデ3案
入力：行き先（学校・遊び・デート・フォーマルなど＋自由入力）、今日着たいアイテム（任意）
処理：
1. 天気を取得（その日の最高・最低気温、降水）
2. **ルールで候補を絞る**（ここはコードで処理）
   - 気温→warmthの範囲
   - 行き先→formalityの範囲
   - 直近N日（初期値3）に着たアイテムは減点
   - 雨なら靴・素材を考慮
3. 絞った候補のメタデータ（＋サムネイル）とProfile、直近のフィードバック履歴をAIに渡し、3案をJSONで返させる
   `{ outfits: [{ itemIds: string[], reason: string, styling_tip: string }] }`
4. IDの実在、カテゴリ構成（トップス＋ボトムス＋靴が最低限揃っているか）を検証する。NGなら再生成（最大2回）、それでもダメならエラーを表示
5. 固定アクセは全案に自動で追加する
表示：切り抜き画像を並べたコーデカード＋理由＋着こなしのコツ（袖まくり・タックインなどの着崩し提案はテキストで）
操作：👍 / 👎 / 「これ着る」（wearCountとlastWornAtを更新）

### 4.4 買い物の相談
1. 商品のスクショまたは写真を貼る（ECサイトでも店頭でもOK）
2. AIが商品の属性を3章と同じ形式で抽出する
3. 手持ちとの照合：
   - **似たアイテムを持っているか**（カテゴリ・色・形が近いものを、類似理由つきで表示）
   - **新しく組めるコーデ数**：その商品を含むコーデを4.3のルールで列挙し、AIで成立するものを判定して数える。代表例を3つ表示する
4. 結論を1行で出す：「買い」「似たの持ってる」「合わせる服が少ない」など

### 4.5 学習（フィードバック）
- 直近のrating・worn履歴を要約してプロンプトに入れる
- 👎が続いた組み合わせ傾向はstyleNotesに自動で追記する（ユーザーが編集できる）

## 5. 余力があれば（MVPが完成してから）
- 着用イメージの生成：ユーザーの全身写真＋コーデから、着用状態の画像を作る（試着・着崩し）。失敗しても4章の機能が壊れないように独立させる
- テイスト切り替え：tasteModeでプロンプトの人格を変える
- 自分のコーデ写真を見せての相談：4.4の照合ロジックを流用して「〇〇を手持ちの△△に替えると良い」と返す
- 1枚の写真から複数アイテムを切り出す

## 6. 実装順
1. プロジェクト作成、PWA化、DexieでDB
2. 4.1 登録（切り抜き→AIタグ→保存）＋4.2 一覧
3. 天気取得
4. 4.3 コーデ提案＋フィードバック
5. 4.4 買い物の相談
6. 4.5 学習
7. 余力枠

各ステップの完了条件：**実際の服を最低10着登録した状態で、そのステップの機能が実機（スマホ）で動くこと。**

## 7. 注意
- APIキーはクライアントに置かない
- 画像はAIに送る前にリサイズする（長辺1024px程度）。コストと速度のため
- IndexedDBのエクスポート／インポート（JSON＋画像のzip）を用意する。端末を替えたときとデモ用
